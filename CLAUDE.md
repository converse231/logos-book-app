## Project

**Quire** (renamed 2026-07-21 from "Logos" — a quire is a gathering of folded pages; the display name, slug `quire`, scheme `quire://`, and bundle id/package `com.quire.app` all use it) — a gamified reading-tracker mobile app. The emotional north star is making readers feel like *literary athletes*: "Before the book, there was the quire. Track every page you read." (renamed from the old Logos tagline "In the beginning was the Word.") Streaks, comeback challenges, variable-reward reading insights, and XP/levels are not features bolted onto a tracker — **gamification IS the product**. (The repo folder `LOGOS-APP` and `LOGOS_BLUEPRINT.md` keep their old names; the blueprint's prose/deep-links still say "logos" — historical, not user-facing.)

React Native + Expo (managed, **SDK 57**), file-based routing via **Expo Router**, written in **TypeScript**. Entry point today is `index.js` → `App.js` (default scaffold); phase **F0** migrates the app to the Expo Router `app/` tree.

> **`LOGOS_BLUEPRINT.md` is the single source of truth.** It is the authoritative 22-section product + technical spec. This file is the working guide; when the two conflict on product or architecture, the blueprint wins. The blueprint marks unverified claims with `[VERIFY]` — confirm those against live SDK/API docs before relying on them.

## Status & approach

**Frontend-first.** We build and refine the entire UI/UX against a typed **mock service layer**, then integrate the Supabase backend later. The repo is still the default Expo scaffold — there is no `app/` tree, no TypeScript, and none of the runtime stack installed yet. Phase **F0** (below) establishes the foundation; everything after it is UI work backed by mock data.

### Critical rule — gamification stays server-authoritative (even while mocked)

The blueprint's single most important architectural rule: **all post-session side effects** (streak, XP, badges, insights, comeback, personal-best) live in **one transactional edge function `complete_session`**, idempotent on `client_uuid`. A naive client that mutates streaks/XP after `insert session` is non-atomic, cheatable, and drifts `level_name`.

**Never compute streak / XP / celebration math inside components.** During the frontend phase we honor this rule by routing everything through a `QuireApi` interface (see *Data layer*) whose **mock implementation** returns realistic results. When the backend lands, the real Supabase implementation drops in with **zero UI changes** — no client-side gamification logic to throw away.

### Expo SDK version (load-bearing constraint)

Expo SDK is **57**. Always consult the versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any Expo-specific code — APIs change between SDK versions.

**iOS Expo Go only supports the single latest SDK.** The App Store Expo Go currently ships SDK 57, so this project must stay on SDK 57 to run on a physical iPhone via Expo Go. Do not downgrade. When Apple ships a newer Expo Go, upgrade with `npx expo install expo@^<new> --fix` then `npx expo-doctor@latest`.

**What the 54 → 57 jump actually cost (2026-09-04), so the next one is cheaper:**

- **`newArchEnabled` is gone from app.json** (SDK 55). The legacy architecture was deleted outright — there is nothing left to opt into.
- **`StyleSheet.absoluteFillObject` was deleted in RN 0.86** (19 sites here). `StyleSheet.absoluteFill` is now a plain frozen object rather than a registered style id, so it is a straight rename and still spreads.
- **expo-router no longer depends on react-navigation** (SDK 56), and Metro *hard-errors* on any `@react-navigation/*` import. `app/(onboarding)/_layout.tsx` had bridged `createStackNavigator` in through `withLayoutContext` purely to get `forHorizontalIOS`; it is now the native `Stack` with `animation: "ios_from_right"` — the same transition, run natively instead of emulated on the JS thread. `@react-navigation/stack` is uninstalled; do not add it back.
- **`@expo/vector-icons` is deprecated** in favour of the `@react-native-vector-icons/*` scoped packages, and `expo` no longer depends on it — so it stays an explicit dependency here. 71 files import it, so the codemod (`npx @react-native-vector-icons/codemod`) is deferred, not forgotten. Deprecated, still working.
- **`expo/fetch` is now `globalThis.fetch`** (SDK 56). `lib/bookSearch.ts` and supabase-js both ride it. If a network behaviour looks off after this upgrade, `EXPO_PUBLIC_USE_RN_FETCH=1` in `.env` restores the old implementation — try that first, not last.
- **RN 0.86 types tab-icon colours as `ColorValue`**, not `string` (an `OpaqueColorValue` from `PlatformColor` is not a string). `AppIcon.color` and `(tabs)/_layout`’s `TabIcon` were widened to match.
- **Minimum iOS is now 16.4** (SDK 56) — drops iPhone 7/7+, 6s/6s+, SE 1st gen, iPad mini 4 and iPad Air 2.
- **Redesigned modules keep the OLD method names as stubs that THROW** (SDK 56/57). `expo-media-library`’s root export is now the class-based API; `saveToLibraryAsync`, `createAssetAsync`, `getAssetsAsync` and 15 more still exist there with their full type signatures and throw `Method X ... is deprecated` at runtime (`src/legacyWarnings.ts`). **`tsc` and Metro both stay silent** — the only symptom is a failure on device, which is exactly how the share-card save broke. `expo-file-system` (15 stubs), `react-native-reanimated` (3) and `react-native-safe-area-context` (2) ship the same pattern. Fix forward (`MediaLibrary.Asset.create(uri)`), or import from the `/legacy` subpath; never assume a green typecheck means an SDK call still works.
- **If a share-card capture ever fails**, `captureRef` has an iOS escape hatch: `useRenderInContext: true` swaps `drawViewHierarchyInRect` for `renderInContext`, which is the documented fallback for views that are not on screen — and the capture target is deliberately parked at `left: -100000`. Both share screens log which half failed (`render` vs `save`), so check Metro before changing anything.
- **Never `catch {}` around a native call.** The bare catch in both share screens is what made the above undiagnosable: a throwing deprecation stub, a capture failure and a full disk all rendered the same "Could not save. Try again." with nothing in the logs. Catch the error, `console.warn` it, keep the friendly copy on screen.

## Front-end architecture rules

These are the non-negotiable client rules distilled from the blueprint (Sections 2/3/4/8/9/20):

- **Reanimated 4, on the UI thread.** Drive the session timer and PPH counter with a shared clock + `useDerivedValue` / `useFrameCallback` — **never** `setState` / `setInterval` (causes dropped frames and full re-renders).
- **The session tracker is a root `Stack` route _above_ the tabs** — not a modal, not inside the tab navigator. This lets the Live Activity / Dynamic Island deep-link straight into it and keeps the tab bar from stealing the bottom thumb zone reserved for session controls. Celebrations are `transparentModal` overlays composited on top of the tracker.
- **`level_name` is identity everywhere** (share cards, notifications, alerts). It is denormalized and trigger-maintained server-side; the client only ever **reads** it. Surface it through `LevelNameBadge`.
- **Format-aware data.** Audiobooks share the `reading_sessions` shape but with `pages_read NULL` and `minutes_listened NOT NULL`. Guard every PPH / page aggregate against `format === 'audiobook'` (COALESCE / filter) — otherwise NaN/Infinity in averages.
- **Offline-first sessions.** Sessions are captured into an MMKV queue with a **frozen `local_date`** and a `client_uuid`; sync drains the queue through the idempotent `complete_session`. Compute `local_date` at capture time, never at sync time.
- **Accessibility from the start.** Every icon-only control (FAB, Stop, share, scanner) needs an `accessibilityLabel`; gate all decorative motion behind `useReducedMotion()`; the invisible-UI Stop control must stay reachable for screen readers even after the timer auto-hides.
- **One keyboard strategy: `KeyboardLift`.** Every keyboard-avoiding surface uses `components/shared/KeyboardLift.tsx` (Reanimated `useAnimatedKeyboard` → `paddingBottom`). Never `KeyboardAvoidingView`: `behavior={Platform.OS === "ios" ? "padding" : undefined}` is a **no-op on Android**, and the two approaches cannot coexist — `useAnimatedKeyboard` calls `setDecorFitsSystemWindows(window, false)` **Activity-wide** on its first subscriber and only restores it when the last unmounts, so once the Library tab mounts, the window stops applying IME insets for the whole session. `app.json` therefore also has **no `softwareKeyboardLayoutMode`** (Expo defaults to `adjustResize`); `pan` would move the window underneath the lift.
- **Staged entrances come from `components/shared/Reveal.tsx`** — `index` for a stagger (65ms step), `delay` for a beat hand-timed against another animation, 430ms either way. It reads `useReducedMotion()` itself; there is no `reduce` prop to forget to pass. This replaced 13 private copies with three prop names and five rhythms.
- **Backdrop policy — no glass blur.** Modals, sheets (`SheetScaffold`), and celebration overlays dim the screen behind them with a **darkened translucent rgba scrim** (≈ `rgba(3,4,6,0.62)` dark / `rgba(17,19,24,0.4)` light), never a `BlurView`/frosted-glass. `expo-blur` is intentionally not a dependency (consistent cross-platform, cheaper on Android). The `SessionControlBar`'s near-opaque `t.glass` fill is a solid translucent surface, not a blur.

## Design system — PAPER & INK (soft-brutalism, light-first)

**Paper & Ink soft-brutalism** (adopted 2026-07-11; supersedes the sharp-cornered "neubrutalism" pass and the earlier dark-first "Quest"/"Ember"/emerald passes). Keeps neubrutalism's **bones** — thick ink borders + **hard offset drop-shadows** — but warms the temperature and **rounds the corners**: warm oat-paper substrate, warm soft-black ink, **flat reward-colour blocks**, **softly-rounded corners**, and hard offset shadows warmed to ink (the hero `Card` adds a whisper of ambient depth). Still no gradients on the substrate, no glass/blur, no glow halos. The full scale lives in `theme/tokens.ts`; retuning it reskins all screens (color/shadow/border are 100% token-driven).

- **Colors:** light `bg #F6EEDF` (warm oat paper) · `bgSec #FCF8ED` (warm cream card — not stark white) · `bgTer #F0E6D3` (inset cream) · `text/ink #241E19` (warm soft-black; also border + hard-shadow colour). Flat reward blocks: `accent/coral #F0764F` (actions, CTAs — warm, inviting) · `ember/streak #F2913F` (amber flame) · `gold/marigold #F3C24C` (XP/levels — ink text on fill; `LIGHT_TOKENS.gold #C8892C` is the readable text/icon tone) · `level/lilac #9A7BD6` (level-up/celebration). **`onAccent #241E19` — INK text on the warm coral fills (the "ink-on-coral" signature; only ever used on accent fills).** Each reward type owns a colour. `danger #B4271B` deep crimson — deliberately a *cooler/deeper* red than the warm coral (never reuse accent for danger). A warm-dark fallback theme exists (`bg #1B1712`, accent `#F6875D`) but light is primary/default.
- **Borders, radii & shadows:** `BORDER_WIDTH 2` / `BORDER_WIDTH_THICK 3`, solid warm ink. `RADIUS` is now meaningful — `sm 10 · md 14 · lg 18 · card 20 · xl 26 · full 9999`; the shared primitives read from it (screen styles still hardcode radii — migrate to tokens over time). Hard shadows via the RN `boxShadow` prop (New Arch), e.g. `SHADOW.card = '4px 4px 0px #241E19'`; helpers `hardShadow(color, offset)` (pure offset) and `softStackShadow(color, offset)` (offset + a whisper of warm ambient, used by `Card` in light mode only). Cards/buttons "press into" their shadow; `PressBlock`/`PrimaryButton` round the shadow block to match the face.
- **Texture:** `ScreenBackground` draws a faint warm **dot-journal grid** (46dp cells, ~2.5px dots, ~6% ink on light / ~5.5% cream on dark) — memoised dot Views (RN's `<Image resizeMode="repeat">` does **not** tile on the New Architecture). Replaced the old blueprint line-grid; the legacy `assets/textures/*.png` + `scripts/gen-textures.js` remain unused.
- **Type:** **Schibsted Grotesk** (`FONTS.ui*`/`display*` — headers + UI + body; UPPERCASE for structural labels) + **JetBrains Mono** (`FONTS.mono*` — all data/metadata/numerics/telemetry: timers, stats, counters; `tabular-nums` on figures) + **Fraunces** (`FONTS.serif`/`serifMedium`/`serifBold` — editorial serif with optical sizing, for HERO DISPLAY moments ONLY: screen titles, section headers, greetings, celebration headlines, book-ish blurbs ≥18px; never small UI/labels). Loaded in `app/_layout.tsx`. (Space Grotesk + Cormorant Garamond were replaced 2026-07-11.)
- **Mascot:** **Q** the fox (`components/shared/Q.tsx`) — a cast of 14 hand-drawn expression PNGs (`assets/q-expressions/`, Paper & Ink palette) placed at emotional beats Duolingo-style: `waving` (onboarding welcome), `reading`/`looking-up`/`shrug` (empty states — Library, Stats, no-active-book), `happy`/`surprised` (session-complete, PB), `confident` (comeback), `concerned` (home at-risk), `levelup` (the level-up modal), `sleepy` (late-night home greeting, 22:00–05:00). Gentle reduced-motion-gated idle bob + optional reward-coloured sparkles; `decorative` prop hides it from screen readers where adjacent text carries the meaning. Usage: `<Q expression="happy" size={n} />`. (Replaced the old hand-built `react-native-svg` `Mascot`/"Fable" face 2026-07-22.) `pointing`/`proud`/`thinking`/`sleeping` exist but are not yet placed.
- **Theme:** default `light`; support light/dark/system per `users.theme`. A `ThemeTokens` object threads through every component (blueprint Section 4).

### Fireflies & Curios — the collection economy (2026-08)

A second currency layered beside XP, and the only thing it buys. **XP measures how far you have come; fireflies are spent.** Keeping them separate is deliberate — a spendable currency has to be able to go down, and `level_name` must never go down.

- **Faucet.** `complete_session` awards `least(25, 3 + pages/10 + minutes/10)` fireflies and banks them on `users.fireflies`, inside the same transaction as streak/XP/badges — server-authoritative like every other post-session effect. The dedupe path returns `firefliesEarned: 0`, so an offline replay cannot double-pay. Migration `20260823000000_fireflies.sql`.
- **Sink.** A **pouch costs 40 fireflies** and rolls one of **13 curios** (acorn, gilded acorn, wild strawberry, four-leaf clover, speckled egg, feather, lantern, turned leaf, moonflower, toadstool, river pebble, pinecone, empty shell). A duplicate refunds **12**. Unowned keys are weighted **3x** against owned. Migration `20260825000000_curios.sql`.
- **The roll is a SECURITY DEFINER RPC (`open_pouch`)** — same rule as streak and XP: a client that picks its own reward is not a reward. Spend, roll, grant and refund are one transaction, and the spend is a **conditional** `UPDATE ... WHERE fireflies >= cost` so two concurrent taps cannot both pass a balance check and overdraw. `public.user_curios` has RLS with a SELECT policy **and nothing else**, so the RPC is its only writer. Deliberately **not** idempotent: unlike `complete_session` nothing replays it, and the client disables the button while in flight.
- **Tuning came from the arithmetic, not taste.** At ~9 fireflies/day a 100-cost pouch with plain random rolls needed 41 pouches / 15 months to finish 13 items, with the *final* item alone averaging 13 pouches. The 3x weighting is what kills that tail: ~22 pouches, ~2.9 months, last item ~5. Constants live in `components/curio/curios.ts` **and** in the RPC's `v_keys`/`v_cost`/`v_refund`/`v_weight` — they must move together, and the `Record<CurioKey, …>` type is the build-time guard against a key existing server-side with no art.
- **Tiers are the sink for a finished collection.** Copies raise a curio Found -> **Polished (3)** -> **Gilded (6)** -> **Luminous (12)**, rendered as a tinted glow over the existing sprite, so the late game costs no new art. Derived client-side in `curios.ts` from `user_curios.count` — there is no tier column and there should not be one. A duplicate that crosses a threshold is treated as a promotion in the reveal (rays, gold, success haptic), not as a refund. Past completion every pouch is a duplicate, so "you had one already" is the wrong frame and the copy switches to tier progress.
- **Pouches are never purchasable with money.** That is what keeps this out of loot-box regulation. Do not add an IAP for them.
- **Two sets, and the prefix IS the set dimension.** A pouch is bought FOR a collection — `open_pouch(p_set)` rolls only that set's keys (`20260827000000_curio_sets.sql`). Set one (`found`, "The forest floor", 13 nature curios) keeps **bare** keys because they are already rows in `user_curios`; set two (`lit`, "Out of the books" — objects out of novels, blurbs that deliberately never name the book) is prefixed `lit-`. There is **no set column** anywhere: `setOf(key)` derives it client-side and the RPC branches on `p_set`. Pooling both into one 24-key hat would roughly double time-to-complete for *both* collections at once and the anti-tail weighting would spread across two shelves, so the reader picks the shelf and the server still picks the prize. The zero-arg `open_pouch()` is kept as a delegating wrapper (→ `'found'`) so builds already in the field keep working — which is also why `p_set` has **no DEFAULT**: a default would make `open_pouch()` ambiguous and break exactly those clients. Both sets are **13**. Adding a key means editing `LIT_KEYS`, `CURIOS` and the RPC's `v_lit` together, or the server rolls a key the app cannot draw.
- **The spend lives on the collection, not the jar** (moved 2026-08-28). The shelf you are looking at IS the shelf the pouch rolls from, so there is no picker anywhere — and the curio lands on the shelf in front of you instead of on a screen you then have to leave (the reveal closing scrolls up to the plinth). `app/jar.tsx` is now balance-only: count, progress to a pouch, one primary button through to the collection showing `n OF 24 FOUND`. `app/collection.tsx` owns the balance, `openPouch(setId)`, the in-flight ref (open_pouch is NOT idempotent, and `opening` state alone cannot stop a double tap) and a pinned footer CTA — `OPEN A POUCH · 40`, or `19 MORE FIREFLIES` when short.
- **Client:** `app/collection.tsx` (**one horizontal page per set, swiped** — a collection is a place, so the gesture moves the whole room: backdrop, plinth, shelf and objects together. Both pages stay mounted and the backdrops cross-fade against the DRAG OFFSET, not on release, so a half-swipe shows half of each; the bottom layer is pinned opaque because two translucent paintings over the root colour sag dark at the midpoint. Page dots live inside the top bar so the affordance costs no vertical space. Rows come from `rowsFor(n)` — 13 → [5,4,4], 11 → [4,4,3]. Tier + copies are one line under the blurb, holding their height when empty so the shelves never jump), `components/curio/PouchReveal.tsx` (the opening sequence, set-agnostic), `components/jar/` (jar, fireflies, Home header button). `QuireApi` gained `getCurios` / `openPouch(set)`. **Tier strip** — `TIERS[].art`, four painted wax seals (oxblood / cream / gold / gold-with-amber). Seal + grade + a progress track + `4/6` in ONE bordered strip attached under the plinth, because that is what it describes: a specimen label's condition line. A seal floating in the gutter plus copies in a bare sentence made two orphans out of one fact, and both read as noise. Reserved height either way so nothing below moves. No entrance spring on it — a bouncing badge reads as a toy. Each set owns a backdrop **and its own scrim strength**: `bg-nook` at 0.44 (bright amber interior) / `bg-library` at 0.22 (cool moonlit library, already a third of the nook's luminance — 0.44 crushed it to near-black so the set read as "the screen went dark" instead of as somewhere else). The scrim lives INSIDE each cross-fading backdrop layer, not as one shared layer on top, so a switch blends two finished looks. **Collections are told apart by colour temperature** — set one amber, set two cool blue; `bg-meadow` (green-gold afternoon) is encoded and waiting for a set three. Warm brass curios also separate far better from a cool ground than from a warm one.
- **Art pipeline — do not `require` the source PNGs.** `assets/tok-*.png` (set one) + `assets/lit-*.png` (set two) + backdrops are **~45MB**; requiring them puts all of it in the app bundle. `assets/curio/*.webp` are cropped to content, scaled so the longest side fills a 320px square, then **horizontally centred and bottom-aligned** (so every curio shares one ground line when standing on a shelf) and encoded at render size: **1.5MB** for both 13-curio sets, four tier seals, shelves, pouch and four backdrops (two collection, two jar). `scripts/gen-curio-art.js` owns that geometry — run it after dropping new source art in `assets/`, never hand-crop. Output name === the CURIO KEY: set one's `tok-` prefix is stripped (`tok-acorn.png` → `acorn.webp`) while set two's `lit-` prefix IS part of the key and stays. Encode quality is tuned so a full re-run reproduces the hand-encoded originals rather than quietly softening them.
- **Known seam:** the jar renders at most `MAX_FLIES` fireflies while a pouch costs `POUCH_COST`. Keep them equal or the jar looks full before you can afford anything. Each fly costs ~6 animated styles on the UI thread, so `MAX_FLIES` is a render budget as much as a design choice.

## Presentations (`presentations/`)

Decks live outside the app but reuse its brand. Rules load from `presentations/CLAUDE.md`;
the `make-deck` skill (`.claude/skills/make-deck/`) runs the full build.

- **One self-contained `.html` file per deck.** No PowerPoint, no slide framework (reveal.js,
  Slidev, Marp — none), no npm, no build step, no dependencies. CSS + JS inline. It opens by
  double-clicking. Only external request is the Google Fonts `<link>`, and it degrades fine.
- `presentations/brand.md` is the visual contract (Paper & Ink, mirrored from `theme/tokens.ts`);
  `presentations/context.md` is the **only** source of facts. **Never invent a number, date,
  link, or quote for a slide** — Quire is pre-launch and has no metrics to quote. Missing fact →
  a visible `[Add link]` marker plus a `[NEEDS FACT]` line in the deck's `outline.md`.
- `presentations/template.html` is the shared engine (nav / overview / speaker notes / copy
  buttons / slide types). A deck copies it and edits **only** the markup inside
  `<main class="deck">`. Never fork its CSS or JS per-deck — new visuals get added to the
  template so every deck inherits them.
- `outline.md` before any slide HTML. One folder per deck, assets copied in (never hotlinked).
- **Never generate images for a deck** — real screenshots and real favicons only; if art is
  missing, write a prompt into `outline.md` for the user to generate.
